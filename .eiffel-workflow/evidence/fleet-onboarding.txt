    cd /d/prod/simple_bnf

ec.sh expands this to:

    ec.exe -batch -config simple_bnf.ecf -target simple_bnf_tests -finalize -keep -c_compile

Run in the FOREGROUND, blocking. `-keep' preserves the DBC contracts in the
finalized code, which matters here: the contracts are the oracle for the
whole-factory sweep test.

Before the final build the whole EIFGENs tree was removed, so this is a clean
compile, not an incremental one:

    rm -rf EIFGENs

7. STUB DETECTION (/eiffel.stub-detect)
================================================================================

Scope: src/ only (production code).

    stub() calls                 0
    TODO / FIXME / XXX / HACK    0
    empty feature bodies         0
    unimplemented externals      0

    EXIT: PASS (0 issues)

Note the distinction: no STUBS, but three real DEFECTS, found by running the
code rather than by scanning it.

  D1  Every choice production raised instead of parsing.
      BNF_PRODUCTION.parse_choice_components split the right side with
      SIMPLE_REGEX.split, which accepts a READABLE_STRING_GENERAL but whose gobo
      backend requires an 8-bit subject. Passing right_side.to_string_32
      violated RX_REGULAR_EXPRESSION.split's `subject_is_string' precondition.
      All 50 choice productions, and make_choice, were unusable.
      FIXED: scan for the alternatives with match_all instead of splitting.

  D2  make_aggregate failed its own postcondition.
      It set is_choice and is_repetition to False but never set is_aggregate to
      True, so `ensure is_aggregate: is_aggregate' and the class invariant
      `exactly_one_type' both failed on every call.
      FIXED: set the flag. make_choice and make_repetition now state all three
      flags explicitly instead of leaning on default initialization.

  D3  28 of the 224 factory productions raised a parse postcondition.
      ECMA-367 writes a repetition's separator as a concrete terminal -
      {Note_entry ";" ...}* - not as the schematic section sign that
      parse_repetition_components looked for, so 27 repetition productions
      extracted no component at all. Bracket, whose right side is the
      terminal-only "[]", extracted none either, because
      parse_aggregate_components recognized construct names and bracketed
      optionals but not quoted terminals.
      FIXED: both extractors widened. The separator stays out of a repetition's
      components - it is punctuation between specimens, not a component of them.

D3 was found by a static sweep of all 224 right sides, then confirmed and
regression-guarded by ECMA367_FACTORY_TESTS.test_every_production_instantiates,
which calls all 224 factory features and lets each production's own contracts
decide whether the parse was sound.

KNOWN DEFECT LEFT STANDING:

  BNF_COMPONENT.make ensures `name.is_empty' while the class invariant demands
  `not name.is_empty'. The two contracts contradict each other, so `create
  c.make' always raises with assertions on. make_from_construct is unusable for
  the same reason - BNF_CONSTRUCT has no create clause and no setter, so a
  construct's name is always empty.

  NOT fixed: repairing it means deciding whether a nameless component is legal,
  which is a design call for the author rather than a bug fix. It is pinned by
  LIB_TESTS.test_component_argumentless_make_is_a_known_defect, which passes
  only while the contradiction stands and fails loudly the day it is repaired.
