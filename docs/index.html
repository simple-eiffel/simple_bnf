Overview

ECMA-367 defines Eiffel in roughly 224 production rules written in BNF-E. simple_bnf turns those rules into a small object model: every non-terminal production is a feature you can call, every production knows which of the three forms it takes and which components it is built from, and a curated set of regular expressions finds specimens of a construct in real Eiffel source text.

The vocabulary is the standard's own (§8.2.2). A component is any class text or syntactically meaningful part of it. A construct describes the structure of a kind of component. A component of a kind described by a certain construct is a specimen of that construct: any class text is a specimen of the construct Class; the identifier your_variable is a specimen of the construct Identifier.

Part of the Simple Eiffel ecosystem.

Status

0.1.0 — first public release. 17 tests, all passing, zero compiler warnings. One of those tests sweeps the whole factory, so all 224 production features are known to build a well-formed BNF_PRODUCTION.

Be clear about what this is: a model of the grammar, not a parser. It classifies and decomposes production rules, and it can tell you whether a snippet looks like a specimen of a construct. It does not build a parse tree from an Eiffel class, and BNF_COMPONENT.specimen is a graph slot that nothing fills yet.

Two further limits, both recorded in the changelog: the pattern registry covers 31 of the 224 productions, not all of them; and BNF_COMPONENT's argumentless make can never succeed, because it ensures an empty name while the class invariant forbids one. A test pins that defect so a repair cannot pass unnoticed.

The Three Production Forms

ECMA-367 §8.2.6–8.2.12 gives every non-terminal exactly one production, in one of three forms. BNF_PRODUCTION detects the form from the right side and decomposes it.

Form Right side looks like What components holds
Aggregate Notes Class_header [Formal_generics] The fixed sequence; optional parts keep their brackets
Choice Deferred | Effective_routine | Attribute One entry per alternative
Repetition {Note_entry ";" ...}* or Digit+ The repeated construct; the separator is excluded

The separator is punctuation between specimens, not a component of them, so a repetition's component list names only what repeats.

Quick Start

Installation

  1. Set the ecosystem environment variable, once, for every simple_* library: 
    SIMPLE_EIFFEL=D:\prod
  2. Add to your ECF: 
    <library name="simple_bnf" location="$SIMPLE_EIFFEL/simple_bnf/simple_bnf.ecf"/>

Ask the standard what a construct is made of

local
    factory: ECMA367_PRODUCTIONS
    production: BNF_PRODUCTION
do
    create factory

    production := factory.class_name
    print (production.construct_name)      -- Class_name
    print (production.right_side)          -- Identifier
    print (production.is_aggregate)        -- True
end

Build a production and let it classify itself

create production.make_from_text ("Feature_body", "Deferred | Effective_routine | Attribute")

print (production.is_choice)           -- True
print (production.components.count)    -- 3
print (production.components [1])      -- Deferred
print (production.is_valid)            -- True

Find specimens in real source text

local
    registry: ECMA367_PRODUCTION_PATTERNS
    regex: SIMPLE_REGEX
do
    create registry
    create regex

    if attached registry.get_pattern ("class_name") as al_pattern then
        print (regex.all_matches_for (al_pattern, "class BNF_SPECIMEN") [1])
        -- BNF_SPECIMEN
    end
end

The Classes

BNF_PRODUCTION

A production rule: construct name, right side, detected form, extracted components, and syntax validation for each of the three forms.

BNF_CONSTRUCT

The abstract syntactic rule a component conforms to (§8.2.2). Currently a name holder only.

BNF_COMPONENT

A syntactically meaningful piece of class text, terminal or not, with a SIMPLE_GRAPH of the specimens that comprise it.

BNF_SPECIMEN

One concrete instance of a construct: the construct's name plus the source text that manifests it.

ECMA367_PRODUCTIONS

The factory. One feature per non-terminal, 224 of them, each returning a parsed and classified production.

ECMA367_PRODUCTION_NAMES

The 223 distinct non-terminal names as a single array, for iterating the whole vocabulary.

BNF_CONSTANTS

Curated regex constants for Eiffel constructs, each with an ensure is_valid clause that compiles the pattern.

ECMA367_PATTERNS

Hand-curated regexes for the high-value productions, each documented with what it matches and worked examples.

ECMA367_PRODUCTION_PATTERNS

The registry: production name in, regex out, or Void when no pattern has been curated for it.

Why 224 features but 223 names: Constant_attribute is generated twice, as constant_attribute_prod (§134) and constant_attribute_2_prod (§183). Both are kept for now so nothing that calls either breaks.

Patterns and Their Reach

A production tells you how specimens are structured. A pattern tells you how to find one in a file. The two are separate on purpose: the grammar is the standard's, the patterns are judgment calls, and judgment calls should be visible as such.

ECMA367_PRODUCTION_PATTERNS.get_pattern answers for 31 productions — class headers and names, feature clauses and declarations, type marks and generics, the instruction and control-flow keywords, the contract clauses, the manifest literals, comments and identifiers. Every other production name returns Void, which is an honest answer and not a failure: ask for a pattern that has not been curated and you get nothing rather than something wrong.

Testing

/d/prod/ec.sh test -config simple_bnf.ecf -target simple_bnf_tests
./EIFGENs/simple_bnf_tests/F_code/simple_bnf.exe

Run the executable from the library root: two tests read src/ and testing/test_data/ by a path relative to the current directory. Every file the suite touches lives inside the repository, so the tests run on any machine that can build the library.

Contracts are compiled in and are themselves the oracle. That is how the whole-factory sweep works: it does not assert 224 separate expectations, it calls all 224 features and lets each production's own postconditions and invariant decide whether the parse was sound.
